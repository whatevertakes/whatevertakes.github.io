# Team publishing guide

1. Draft in a branch; use Markdown in src/pages/blog/ (English) or src/pages/ko/blog/ (Korean).
2. Set title, description, date, category, author and layout.
3. Link primary sources and reproducible public evidence where appropriate.
4. Separate a reproduced known issue from original findings and external validation.
5. Obtain review from a teammate, check disclosure status and avoid private details.
6. Run npm ci and npm run build before merging.

Use Korean or English as appropriate; publish both versions of major research reports when possible. Add reciprocal translation URLs to frontmatter when both versions exist (for example /ko/blog/research-direction/ and /blog/research-direction/). Do not add translation links until the corresponding page exists. No invented results or claims of acceptance.
